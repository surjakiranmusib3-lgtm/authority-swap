# Part 2a draft protocol | 14 November 2026 IST

**Status: draft design only. No question has been blind-verified, baseline-tested, or admitted to the experiment.** Do not run any model on these questions until later authorized parts.

## Bank construction

- Target at least 90 **main candidates**: 30 easy, 30 medium, 30 hard. Add 8 pilot-development, 16 pilot-acceptance, and 24 genuine-correction candidates, all with distinct IDs and factual stems. This yields 138 drafted candidates. Main, pilot and correction banks must not share an item or paraphrased stem. None comes from the prior *Counting Evidence by Origin* synthetic cases.
- Candidate tiers are provisional. **Easy** asks one direct, familiar fact; **medium** compares or selects among two facts from an official source; **hard** requires a bounded two-step comparison or a less familiar but source-explicit fact. Difficulty is not established until pilot/model baselines. A label is not an eligibility result.
- The question file omits drafted keys. Keys are kept separately so a Part 2b reviewer can derive the answer from the cited primary source **before** looking at the drafted key. Each candidate has a source URL and rough locator. Exact supporting passage, access date, alternative-false explanation, and independent key derivation are Part 2b work. Broken sources or ambiguous alternatives must be revised or removed there.
- Use stable, low-stakes facts from at least five domains, including sources beyond NIST/NASA (proposed: BIPM, IUPAC, USGS, NOAA, Smithsonian/Library of Congress/NPS/NIH). Avoid current statistics, politics, personal data, medical advice and dosing. Source authority and actual item correctness remain unverified in this draft.
- Per-model main eligibility requires a correct baseline answer in **both A/B orders**. The same rule applies when analyzing pilot eligibility. Primary estimates use each model's eligible items. Any direct cross-model contrast must use the shared eligible intersection or explicitly account for different item populations; comparing unadjusted model rates would confound model behavior with item selection. All four false-rebuttal branches preserve the wrong answer and factual rationale; three wording sets rotate evenly across questions. Genuine-correction candidates are chosen now, before model errors or reversals can influence selection; their scripted wrong initial answer and true correction will be frozen later.

## Part 3 model and credit plan, not executed here

- Pilot up to **five** candidate models: local Qwen2.5-1.5B-Instruct and SmolLM2-1.7B-Instruct plus up to three hosted models chosen before the pilot from user-named possibilities (`gemma-4-31b-it`, `qwen3.8-27b`, `qwen3.5-397b`, `glm-5.2`). The user reports that the hosted API quotes credits per million tokens; exact availability, model IDs, credit rates and settings are **unverified** until Part 3. Main run uses at most **three** models that pass pilot gates. Run local models one at a time; Part 3 measures CPU throughput first and considers GPU offload only if needed.
- Part 3 may make **at most five total hosted smoke-test calls** to check whether the user-reported credits actually cover hosted inference. Ask the user to report dashboard balance before and after, without inferring the balance from a prior message. Never print or log `ADAPTION_API_KEY`; the user sets it as an environment variable. List models available to that key and check `temperature`, `seed`, `max_output_tokens`, log probabilities and reasoning controls; pin one reasoning setting per model and record unsupported controls. Capture input/output token usage and credits per call.
- Hard project cap: **150 Adaption credits**, inclusive of smoke tests, pilot, correction and any later hosted main calls, unless the user explicitly raises it. Before a hosted call, reserve a conservative worst-case credit estimate from verified model pricing and bounded input/output tokens; halt if the next call could exceed the remaining cap. If pricing or usage cannot be bounded, do not call. Part 2a spends **zero** credits. Report hosted-credit use and prior-project overlap in the eventual paper.

## Proposed focal model selection rule, to freeze before pilot

From the predeclared candidate list, first exclude a model that fails parseability, paired completion, both-order eligibility, runtime/credit feasibility, or the pilot floor/ceiling gates. The existing acceptance target is at least 12 eligible items out of 16, at least 95% parseable replies, and at least 90% complete eligible condition sets; revisit these thresholds only **before** outcomes if the graded pilot makes them impossible. For the remaining candidates, select the focal model by (1) largest number of both-order eligible **pilot** items, (2) lower projected cost to finish the planned main bank, and (3) a fixed, recorded model-ID tie-break. Do not rank on the pilot's expert-minus-ordinary contrast or on main outcomes. Select up to two additional passing models by a predeclared cost/coverage rule within the credit cap.

**Critique:** Sixteen acceptance items make eligibility and floor/ceiling estimates noisy. Selection can favor a chance-high eligibility rate and may favor larger models; a Qwen model near saturation may fail despite its replication value. Pilot-based model choice does not bias the later paired estimate on a genuinely disjoint main bank, but the result is conditional on the selected model and cannot be sold as representative of all models. Preserve and report all five candidates' pilot gate results. If no model passes, stop and revise the protocol before any main run. The current working title says “Small Local Models”; a hosted main model would require a user-confirmed title update before Part 7.
